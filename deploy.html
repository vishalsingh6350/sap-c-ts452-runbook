C_TS452 Deploy
Setup · do this once

Publish the runbook on GitHub Pages

Plain static HTML, no build step, no dependencies. About ten minutes from nothing to a live URL you can open on your phone.

7 steps ~10 min Read step 1 before you commit anything
☠Read this first — do not commit the SAP PDF

C_TS452_EN_2601_Task_Instructions.pdf is SAP copyrighted courseware. On a free GitHub account Pages only works from a public repository, so anything you commit becomes publicly downloadable and indexable.

Keep the PDF out of the repository. Every path in this guide does that — either by publishing only the Guides folder, or with a .gitignore. Your own notes are safe: group number, ticks and document numbers live in your browser, never in the site files.

Choose the repository layout

GitHub Pages serves from the repository root or from a folder named /docs. Nothing else. That is the only real decision here.

Option A — a repo that contains only the site Recommended

Copy the contents of Guides into a new empty folder and publish that as the repo root. The PDF is never anywhere near the repository, so it cannot leak by accident, and Pages needs no special setting.

Cost: the site lives in a different folder from your working copy, so you edit in one place and copy across. For a runbook you rarely change, that is nothing.

Option B — one repo, site in /docs If you want everything together

Rename Guides to docs, add a .gitignore that excludes the PDF, and point Pages at /docs.

Risk: one careless git add -A with a broken .gitignore publishes the PDF. Check git status before your first commit.

ℹRepository name decides your URL
A repo called sap-c-ts452-runbook gives you https://<you>.github.io/sap-c-ts452-runbook/. A repo named exactly <your-username>.github.io gives you the bare https://<you>.github.io/ instead. Either works — all links in the runbook are relative.

Prepare the folder

Check Git is installed. Use Git Bash on Windows — these commands assume it.

Git Bash
git --version

No output? Install Git for Windows from git-scm.com, then reopen the terminal.

Option A — copy the site to its own folder

Git Bash
# create a clean folder next to your project
mkdir -p ~/Documents/sap-c-ts452-runbook

# copy the site into it, including .nojekyll
cp -r "/c/Users/visha/Documents/Projects - 2026/SAP Certification/Guides/." \
      ~/Documents/sap-c-ts452-runbook/

cd ~/Documents/sap-c-ts452-runbook
ls -a

You should see index.html, task3.html … task7.html, edge-cases.html, deploy.html, assets/, sw.js, manifest.webmanifest, README.md and .nojekyll. No PDF.

Option B — rename the folder and exclude the PDF

Git Bash
cd "/c/Users/visha/Documents/Projects - 2026/SAP Certification"
mv Guides docs

# keep the courseware out of the repository
printf '*.pdf\n' > .gitignore

# prove it worked before committing
git init
git status --short
⚠Stop and read the output
If C_TS452_EN_2601_Task_Instructions.pdf appears in that list, the ignore did not take. Fix it before committing — a file that has been committed once stays in the history even after you delete it.

Create the repository on GitHub

1
Go to github.com/new
2
Name it, for example sap-c-ts452-runbook
3
Set visibility to Public — Pages on a private repo needs a paid plan
4
Do not tick "Add a README", "Add .gitignore" or "Choose a license" — an initialised repo makes the first push harder
5
Click Create repository and leave the page open — you need the URL it shows

Or, if you have the GitHub CLI:

Git Bash · GitHub CLI
gh auth login
gh repo create sap-c-ts452-runbook --public --source=. --remote=origin

Commit and push

Run these from inside the folder you prepared in step 2. Replace <you> and the repo name.

Git Bash
git init
git add .
git status --short          # last chance: no .pdf in this list
git commit -m "Add C_TS452 exam runbook"
git branch -M main
git remote add origin https://github.com/<you>/sap-c-ts452-runbook.git
git push -u origin main
⚠If the push asks for a password
GitHub stopped accepting account passwords over HTTPS. Either run gh auth login once, or create a personal access token (GitHub › Settings › Developer settings › Personal access tokens › Tokens (classic), scope repo) and paste the token where it asks for the password.
ℹLine-ending warnings are harmless
warning: LF will be replaced by CRLF on a Windows machine changes nothing about how the site is served. Ignore it.

Turn on GitHub Pages

1
Open the repo › Settings › Pages (left sidebar, under "Code and automation")
2
Source: Deploy from a branch
3
Branch: main
4
Folder: / (root) for Option A  ·  /docs for Option B
5
Save, then wait. The first build takes one to three minutes; the Pages panel shows the URL when it is live

Your URL:

https://<you>.github.io/sap-c-ts452-runbook/

Watch the build under the Actions tab if it seems stuck. A green tick there but a 404 in the browser almost always means the wrong folder was selected in step 4.

Changing the runbook later

Git Bash
git add .

git push
☠Bump the cache or nobody sees your change

The service worker caches the site so it works offline. If you edit any file, open sw.js and change the version:

var CACHE = 'cts452-v1';  →  var CACHE = 'cts452-v2';

Commit that in the same push. Without it, anyone who already opened the site keeps seeing the old version and will think your edit did not deploy.

Troubleshooting
What you seeCause and fix
404 at the Pages URL Most likely the first build has not finished — give it three minutes. Then check: Pages is enabled, the branch is main, and the folder matches your layout (/ (root) vs /docs). Also confirm the repo is public if you are on a free plan.
404 on the URL, but /index.html works You pointed Pages at a folder that has no index.html at its top level. Re-check the folder setting.
Page loads but has no styling The stylesheet 404s. Open the browser console. Almost always a case problem — GitHub Pages is case-sensitive, Windows is not, so Assets/App.css works locally and fails live. Everything here is lowercase; if you renamed anything, match it exactly.
Some files are missing from the live site Jekyll is hiding anything whose name starts with _. The repo already has a .nojekyll file — make sure it was committed (git ls-files | grep nojekyll). Hidden files are easy to leave behind when copying folders in Windows Explorer.
Old version keeps showing after a push The service worker cache. Bump CACHE in sw.js and push again. To force it on your own device: DevTools › Application › Service Workers › Unregister, then hard reload (Ctrl+Shift+R).
src refspec main does not match any You pushed before committing. Run git add . and git commit first.
remote origin already exists Replace it rather than adding: git remote set-url origin https://github.com/<you>/<repo>.git
Support for password authentication was removed Use gh auth login, or a personal access token as the password. See step 4.
Pages section is missing in Settings Private repo on a free plan. Make the repo public, or upgrade.
You committed the PDF by mistake Deleting it in a later commit is not enough — it stays in the history and stays downloadable. Simplest safe fix: delete the repository on GitHub, add the .gitignore, and push again from a fresh git init.
Copy buttons do nothing on the live site They should work — Pages is HTTPS, which the clipboard API requires. If they fail, the page falls back to a hidden textarea; check the console for a blocked-permission message.
Two things worth knowing
  1. A Pages site is always publicly readable. Even from a private repo on a paid plan, the published URL is open to anyone who has it. The runbook itself contains nothing personal — your group number, ticks, timers and logged document numbers are stored in your own browser and are never part of the site — so this is fine, as long as the SAP PDF stays out.
  2. Do not rely on the live site during the exam. The assessment instructions tell you to close other browser sessions and avoid extra tabs. Keep using the local copy on exam day; the Pages version is for studying, for your phone, and for reading on a second device.
✓Once it is live
Open it on your phone and use Add to Home Screen — the manifest makes it launch full-screen like an app, and the service worker keeps it working with no signal.

Hidden prerequisites — config the exam text assumes exists
☠These are the ones that cost the most time
Each is a piece of configuration that the task text takes for granted. On a clean practice system it usually exists. When it does not, the step is simply impossible and the error message points somewhere else entirely.

Task 5.6 FI tolerance group must exist before the supplier will accept it

You create the vendor-specific tolerance, go to the supplier master, type C## and get:
Entry C## does not exist in T043G – check your entry
Fix
OBA3 — SPRO › Financial Accounting › Accounts Receivable and Accounts Payable › Business Transactions › Outgoing Payments › Manual Outgoing Payments › Define Tolerances (Vendors). New entries: company code 1010, tolerance group C##, currency EUR, values all zero. Then return to the supplier. Full chain on the Task 5 page.

Task 3.8 Flexible workflow may not be switched on for purchase orders at all

You build CERT##, activate it, create the purchase order — and it saves clean with no approval step. The workflow definition is fine; the scenario is not active.
Check, in this order
  1. SPRO › Materials Management › Purchasing › Purchase Order › Flexible Workflow for Purchase Orders › Activate Flexible Workflow — the scenario must be switched on.
  2. Is a classic release strategy configured for document type ZNBF? Classic release and flexible workflow are alternatives — if the classic strategy applies, your workflow never fires. Look at the purchase order’s Release strategy tab: if it shows a release group and code, the system is on classic release.
  3. Is your workflow ordered above any catch-all auto-approve workflow in the app’s list?

If classic release is what the system uses, the exam step is still about getting the order released and the output processed — do that, and note it. Do not burn 20 minutes fighting the framework.

Task 4.7 Unplanned delivery costs may be configured to bypass the purchase order

The exam says “post the transportation costs to the purchase order”. That only happens if the company code is configured to distribute unplanned delivery costs among the invoice items. The alternative setting books them to a separate G/L account and the order value never moves.
Check
SPRO › Materials Management › Logistics Invoice Verification › Incoming Invoice › Configure How Unplanned Delivery Costs Are Posted. For company code 1010 the entry should be distribute among invoice items (the blank / default option), not post to separate G/L account.

Task 7.5 · 7.10 Classic MRP (MD02) vs MRP Live (MD01N)

The guide uses MD02 because it exposes the Create purchase req. parameter that the exam result depends on. If MD02 is not available, use MRP Live — MD01N, or the Fiori Schedule MRP Run app.
What changes
MRP Live has no Create purchase req. control — for an externally procured material (procurement type F, which you set on MRP 2) it creates purchase requisitions directly, which is what you want. Run it for material T-RC5## and plant 1010, then check MD04 exactly as described. Do not use planning mode 3 / “delete and recreate” on the second run — it can wipe planning data.

Task 5.7 Seeing that the invoice was actually reduced

Automatic invoice reduction is silent if you are not looking in the right place. The columns that show it live in a different item list layout.
How to see it
In MIRO, change the item list layout variant to the Invoice Reduction one. It adds the Correction ID column plus the vendor’s quantity and amount. A reduced invoice also produces a second document (the complaint / credit memo) — check the follow-on documents after posting.

If the system does not reduce automatically, the same layout lets you do it by hand: set Correction ID to Vendor error: reduce invoice and enter the vendor’s figures. That is a legitimate fallback, but do the tolerance config first — the config is what is graded.

Task 3.1 The plant copy asks several questions — answer them differently

How to answer
  • “Copy all dependent entries?” → Yes. This is the customizing you actually need.
  • Anything offering to copy material master data, stock or transaction data → No / skip. It can run for many minutes and you do not need it.
  • Read the completion log before leaving. A copy that ended in errors leaves a half-built plant that looks fine in OX10.
Blocking errors — message to cause to fix

Task 3.9 Purchase order rejects the new supplier

Partner function VN is not defined / no partner roles maintained
The business partner has a purchasing org segment but no partner functions.
Fix
BP → SP-C## → role Supplier → Purchasing Org P0## → tab Partner Functions. Add VN (vendor); add OA and PI if the system insists. Usually filled automatically from the account group — when it is not, this is the error you see.

Task 5.1 No component screen appears on the subcontracting order

You set item category L and press Enter, and nothing explodes.
Causes, in order of likelihood
  1. Item category is not actually L — check the column, not what you meant to type.
  2. The material has no bill of material for plant 1010. Check with CS03 (material T-FL4A##, plant 1010, BOM usage 1 production or 3 universal).
  3. A BOM exists but not for that plant or that usage.

If there is genuinely no BOM, you can still enter the component manually on the component screen — add T-FL4A1## with the quantity the task implies. The process still posts.

Task 3 · any goods movement in a new plant Account determination fails

Account determination for entry ... not possible
The new plant is not assigned to a valuation grouping code, so OBYC cannot resolve an account.
Fix
OMWD — assign valuation area Y0## to the same valuation grouping code that plant 1010 uses. A correct Copy org. object normally brings this across; a hand-built plant never does.
Task 3 has no goods movement, so this usually stays dormant — but it is the classic symptom of a plant that was created instead of copied.

Task 6.1 The 10 % discount condition will not go in

Neither RA01 nor RA00 appears in the header condition list.
Fix
The condition type must be in the calculation schema assigned to purchasing org 101C and the supplier’s schema group. Open the header conditions and press F4 on the condition type field to see what is available, then take any percentage discount condition offered. The graded fact is a 10 % discount at header level, not the specific four characters.

Task 6.1 Item category W demands a target value

You leave quantity and price empty, as you should, and the item still will not save.
Fix
In a value contract, a W item can require its own target value at item level. Put a sensible figure in — anything up to the header target of 100000,00, for example 50000,00. The header target value is what the exam names, so leave that at 100.000.

Task 6.3 Movement 103 refused on an item

GR blocked stock is only possible for a stock item.
Fix
Post 103 for item 10 (B520-5##) only. Untick Item OK on the two cost-center items — an account-assigned item is consumed on receipt and cannot sit in blocked or quality inspection stock.

Task 7.9 MRP ignores the source list line

Run #2 produces a requisition with no supplier, or with the old one.
Check all four
  • The source list line’s validity covers the requirement date — the requirement is next month, so a line valid only until the end of this month is invisible to it.
  • The contract itself is valid on that date (it starts on the 1st of this month, so it is).
  • Both Agreement and Item are filled.
  • MRP = 1 on the contract line, and blank on the info-record line.

Task 7.2 “Source list requirement” blocks procurement

Source list requirement not fulfilled
Ticking Source list on MRP 2 makes the source list mandatory — every procurement then needs a valid entry.
Fix
Either maintain the source list properly (which you are doing anyway), or untick the flag on the material. The exam does not require the flag — it requires MRP to find a source.

Any task Object locked by your own other session

Material T-RC## is currently locked by user TS450-##
You left the same object open in another window or another mode.
Fix
Close the other window. If it persists, SM12 → enter your user → find the lock entry on that object → delete it. Only ever delete your own locks.
Habits that prevent most of the above
  1. One SAP window per object. Most lock errors are self-inflicted.
  2. Save before you switch tasks. A session timeout loses everything unsaved, and the practice system will time out if you read this page for ten minutes.
  3. Read the status bar after every save. “Document 45000123 created” is your evidence. Write the number down immediately — you will need it two steps later.
  4. Double-click any message you do not understand for the long text. It usually names the exact table or field that is missing.
  5. If a field you need is not on screen, it is hidden by a layout: check Personal Settings in ME21N / ME51N, the item detail tabs rather than the overview, or the list layout variant in MIRO.
  6. When a step will not go through after two honest attempts, log it, skip it, move on. Come back only if time remains. Five tasks are independent; a stubborn step is not worth three others.
